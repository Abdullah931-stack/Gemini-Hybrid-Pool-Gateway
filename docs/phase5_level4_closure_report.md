## 2. البرهان الرياضي الحاسم لألفة الجلسة (ADR-07 Verification)

تم إثبات وتحقيق المعادلة الحاكمة لأولوية الحسابات رياضياً وعملياً:
$$P_{\text{web}, i} = G_{\text{web}, i} \times S_i \times \tau_{\text{web}, i} \times \frac{(0.95 - U_{5h, i}) \times (0.98 - U_{w, i})}{D_{\text{conc}, i}}$$

حيث تم تعريف مقام التوازي المشروط بالصيغة:
$$D_{\text{conc}, i} = \begin{cases} 1 + 0.25 \times C_{\text{web}, i} & \text{إذا كان } S_i = 1.35 \text{ (استكمال جلسة مفتوحة)} \\ (1 + C_{\text{web}, i})^2 & \text{إذا كان } S_i = 1.0 \text{ (جلسة جديدة أو بدون ألفة)} \end{cases}$$

### نتائج البرهان:
- **الحساب صاحب الجلسة المفتوحة (مع طلب جارٍ $C=1$):**
  $$D_{\text{conc}} = 1.0 + 0.25(1) = 1.25 \implies \frac{S}{D_{\text{conc}}} = \frac{1.35}{1.25} = \mathbf{1.08}$$
- **الحساب الفارغ الخامل المنافس ($C=0$ ومحادثة جديدة $S=1.0$):**
  $$D_{\text{conc}} = (1.0 + 0)^2 = 1.00 \implies \frac{S}{D_{\text{conc}}} = \frac{1.00}{1.00} = \mathbf{1.00}$$
- **النتيجة القطعية:** $\mathbf{1.08 > 1.00}$؛ وبذلك تظل الجلسة متفوقة حسابياً وتستكمل على نفس الحساب دون انقطاع، مما يوفر استهلاك الذاكرة والنطاق الترددي ويمنع إعادة ترطيب السياق غير الضرورية.
- **في حال محادثة جديدة على حساب به طلب جارٍ ($C=1, S=1.0$):**
  $$D_{\text{conc}} = (1+1)^2 = 4.0 \implies \frac{S}{D_{\text{conc}}} = \frac{1.0}{4.0} = \mathbf{0.25} \ll 1.00$$
  مما يدفع المحادثات الجديدة تلقائياً نحو الحسابات الفارغة.

## 3. محرك مصافحة البث غير الفارغ والاستجابة الصفرية للانقطاع (ADR-10)

1. **التقاط القطع الأولية:** استهلاك القطع الأولية وحجزها مؤقتاً في مخزن (`buffered_chunks`) بحد أقصى `HANDSHAKE_MAX_BUFFER_CHUNKS = 15`.
2. **التحقق الدلالي من المحتوى:** فحص وجود نص حقيقي في `content` أو تفكير في `reasoning_content` أو أدوات في `tool_calls`.
3. **الربط التسلسلي المضمون:** إطلاق المولد التسلسلي `chain_async_iterators` فور التحقق لتسليم القطع المحجوزة أولاً ثم باقي التدفق الحي.
4. **التعافي اللحظي من البث الصفري (Zero-Byte Stream EOF):**
   - اعتراض انتهاء البث دون أي محتوى أو ورود خطأ 429 / 403 أو خطأ شبكة.
   - إنقاص عداد التوازي للحساب المتعثر فوراً: `account.active_requests = max(0, account.active_requests - 1)`.
   - استبعاد الحساب مؤقتاً عبر `excluded_ids`.
   - الانتقال السلس للحساب البديل (Cross-Channel أو داخل نفس القناة) وتقديم البث للعميل دون شعوره بأي خلل.
5. **حماية التوازي من التسرب (Zero Concurrency Leak):** إثبات عدم تسرب أي عداد توازي في كافة المسارات عبر كتل `finally:`.
